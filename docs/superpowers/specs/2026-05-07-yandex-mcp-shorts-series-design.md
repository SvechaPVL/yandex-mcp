# Yandex MCP Shorts Series — Design Document

**Дата:** 2026-05-07
**Статус:** Утверждён к реализации (ожидает финального ревью)
**Автор:** Claude (по запросу владельца проекта)
**Контекст:** Серия вертикальных коротких видео (шортсов) о MCP-сервере `yandex-mcp` для портфолио / tech-блога.

---

## 1. Цель и аудитория

**Цель:** Личный портфельный туториал — серия публичных видео, демонстрирующих работу автора над production MCP-сервером и реальные результаты его применения. Серия:

- Усиливает портфолио для рекрутёров / tech-сообщества (особенно RU-сегмента)
- Привлекает внимание к open-source проекту `SvechaPVL/yandex-mcp` на GitHub
- Демонстрирует практический опыт работы с MCP-серверами и AI-управлением рекламой

**Аудитория:**
- Разработчики, интересующиеся MCP / AI-агентами / автоматизацией
- Маркетологи и арбитражники, готовые рассмотреть AI как инструмент
- Tech-рекрутёры RU/CIS

**Не аудитория:**
- Иностранные англоязычные разработчики (есть английский README на GitHub, но шортсы на русском)
- Менеджеры без технического контекста

## 2. Формат и площадки

| Параметр | Значение |
|---|---|
| Тип контента | Серия вертикальных шортсов |
| Длина одного ролика | ≤60 секунд (целевая 58 сек) |
| Соотношение сторон | 9:16 (1080×1920) |
| Frame rate | 60fps (если `mcp-video` стабильно справится; иначе 30fps) |
| Кодек | H.264, целевой битрейт ≤8 Mbps, размер файла ≤80 МБ |
| Язык | Русский |
| Количество роликов | 6 |

**Площадки публикации (multi-cast):**
- YouTube Shorts (главная)
- VK Clips
- Telegram-канал автора
- Instagram Reels (опционально)

**Расписание публикации:** один ролик каждые 2 дня в течение 11 дней.

---

## 3. Угол атаки серии

**"Numbers-first"** — каждый шортс открывается шок-цифрой и фокусируется на одном измеримом результате применения MCP-сервера к реальной рекламной кампании (asiapk.ru / Авто из Азии под капотом).

Каждый ролик строится по единому 5-актному шаблону (см. раздел 5).

### Шорт #1 — Bounce −7.5 пп

- **Hook:** "Минус 7.5 пунктов отказов за 6 дней. Без программистов."
- **Setup:** Скрин Метрики, ЕПК-кампания, bounce 31.2% подсвечен красным
- **Reveal:** Claude Desktop → промпт *"покажи воронку и скажи где утечка"* → MCP `metrika_get_report` → таблица: mobile bounce 40.8%, 0 лидов из 169 виз/нед → промпт *"mobile -90%, Сев.Кавказ -90%, Владивосток -90%"* → MCP `direct_set_bid_modifier` применяет
- **Result:** bounce 23.7% (-7.5pp), LEAD_CAPTURE_SUBMIT 0.14 → 0.83/день (×5.9)
- **CTA:** "Это первый из шести. Дальше — 80 минус-слов за 3 минуты. Подпишись."

### Шорт #2 — Конверсия попапа ×5.9

- **Hook:** "В 5.9 раза. Во столько раз выросла конверсия попапа после одного промпта."

- **Reveal:** Claude через MCP анализирует LEAD_CAPTURE цели (open / close / submit) → находит узкое место → корректировки аудитории
- **Result:** 0.14 → 0.83/день (×5.9)
- **CTA:** "Дальше — детектив. Как Claude вычислил фейковые лиды по Windows 7."

### Шорт #3 — 80 минус-слов

- **Hook:** "Раньше я искал минус-слова неделями. Сейчас — 80 штук за 3 минуты."

## 6. Production stack (Подход 1 — AI-нативный)

### Инструменты

| Слой | Инструмент | Роль |
|---|---|---|
| Сценарий | Claude (этот агент) + CLAUDE.md проекта | Источник фактов, написание текста, ревизии |
| Запись face-cam | OBS Studio, сцена `Portrait 1080×1920` | 6 hook + 6 CTA подряд за одну сессию |
| Запись voice-over | OBS Studio, сцена `Voice-only` | 6 voice-tracks подряд за одну сессию |
| Запись screencast | `mcp-video` (Playwright + FFmpeg, 60fps) | Браузерные screencast'ы Yandex.Директ / Claude Desktop с zoom/pan |
| Монтаж | `video-edit` MCP (FFmpeg-обёртка) | Клейка клипов, оверлеи, on-screen графика |
| Субтитры | Whisper через `video-edit` MCP | Word-level транскрипция RU с initial_prompt лексикой |
| TTS (опц.) | ElevenLabs MCP | Только для b-roll отбивок если потребуется (по умолчанию нет) |
| Финальный полиш (safety net) | CapCut Desktop | Если `video-edit` MCP не справится с эффектом |
| Публикация | Веб-интерфейсы платформ | Вручную, ~5 мин на платформу |

### Ключевые архитектурные решения

1. **Voice-over для всех 6 роликов пишется одной сессией** — критично для звукового однородия (один уровень громкости, одно расположение микрофона, одна акустика).
2. **Face-cam intros + outros — отдельная единая сессия** — один outfit, один свет, один фон → серия выглядит цельно.
3. **Screencast'ы через `mcp-video` под управлением Claude** — каждый screencast = Playwright-сценарий, гарантирует чистую запись без curser-промахов и notification-баннеров.
4. **`video-edit` MCP — главный монтажёр** — на вход клипы + voice + субтитр-таймкоды + раскадровка с эффектами, на выход готовый mp4 9:16.
5. **Контрольная точка после Шорта #1** — единственный способ верифицировать экспериментальный пайплайн без выгорания.

## 7. Workflow (5 фаз)

### Фаза 0 — Сетап (Ты, ~3 ч, один раз)

1. Установить `mcp-video` и `video-edit` MCP в Claude Desktop / Claude Code
2. `npx playwright install`
3. OBS Studio: создать сцены `Face-cam Portrait 1080×1920` и `Voice-only`
4. Тестовая запись 30 сек в обеих сценах → проверить уровни звука и качество видео
5. Создать рабочую папку `~/projects/yandex-mcp-shorts/` со структурой: `scripts/`, `face-cam/`, `voice/`, `screencasts/`, `final/`, `assets/music/`
6. Скачать музыкальный трек (один на серию) из YouTube Audio Library / FreePD
7. Подготовить SFX-набор (whoosh, bell, bass-drop)

**Gate 0:** Пользователь подтверждает работоспособность инструментов.

### Фаза 1 — Pre-production (Claude, ~2 ч)

1. Финальные сценарии всех 6 шортсов с тайм-кодами → `scripts/short-N.md`
2. Раскадровка с описанием on-screen overlays и цветов → `scripts/storyboard.md`
3. Playwright-сценарии для screencast'ов → `screencasts/scripts/short-N.spec.ts`
4. Пользователь читает, даёт правки
5. Claude применяет правки

**Gate 1:** Пользователь одобряет сценарии. До этой точки запись не начинается.

### Фаза 2 — Запись (Ты, ~1 ч суммарно)

| Шаг | Что | Длит. |
|---|---|---|
| 2.1 | Все 6 face-cam hooks (3-4 дубля каждый) | 20 мин |
| 2.2 | Все 6 face-cam CTAs | 15 мин |
| 2.3 | Все 6 voice-tracks (целевая громкость −19 LUFS) | 25 мин |
| 2.4 | Передать файлы Claude | 5 мин |

### Фаза 3 — Машинная сборка (Claude, ~3 ч)

1. `mcp-video` запускает Playwright-сценарии → 6 screencast'ов 1080×1920 60fps
2. Whisper генерирует word-level субтитры → `voice/short-N.srt`
3. `video-edit` MCP собирает финальные ролики (face-cam intro → screencast → face-cam outro), накладывает voice, субтитры, on-screen графику, музыку, SFX
4. Экспорт в `final/short-N.mp4`

**Контрольная точка после Шорта #1 (Tracer Bullet):**
- Если ок → собираем оставшиеся 5 параллельно
- Если местами лагает → гибридный режим (MCP только там где работает)
- Если фейл → откат на Подход 2 (OBS+CapCut) для роликов 2–6

### Фаза 4 — Полиш (Ты + Claude, ~1.5 ч)

1. Пересмотр всех 6 роликов на телефоне (вертикалку лучше тестить там)
2. Список правок
3. Claude применяет правки через `video-edit` MCP
4. Финальный re-watch
5. Claude генерирует миниатюры (cover-frames) и тексты постов для каждой платформы

### Фаза 5 — Публикация (Ты, по дням)

День 1: Шорт #1 на YouTube Shorts + VK Clips + TG + Reels
Через 24 ч: сбор аналитики Шорта #1
Решение: оптимизировать оставшиеся ролики или публиковать как есть
Дни 3, 5, 7, 9, 11: остальные шортсы по расписанию

### Сводка по времени

| Фаза | Активный человеческий труд | Время Claude |
|---|---|---|
| 0 — Сетап | ~3 ч | — |
| 1 — Сценарии | ~30 мин ревизии | ~2 ч |
| 2 — Запись | ~1 ч | — |
| 3 — Сборка | — | ~3 ч |
| 4 — Полиш | ~1 ч | ~30 мин |
| 5 — Публикация | 11 дней × 30 мин | — |
| **Итого** | **~7 ч** активного + 5.5 ч публикации | **~5.5 ч** |

## 8. Риски и контингенции

### MCP-стек

| Риск | Вероятность | Митигация |
|---|---|---|
| `mcp-video` не пускает Playwright в Yandex.Директ (auth/captcha) | Высокая | План Б: запись UI вручную в OBS, MCP оставить для Claude Desktop |
| zoom/pan-эффекты mcp-video кривые | Средняя | Отключить эффекты в `mcp-video`, делать post-zoom через `video-edit` или CapCut |
| `video-edit` MCP не понимает 9:16 | Низкая | Передавать `-vf "scale=1080:1920,setsar=1:1"` или экспорт в CapCut |
| Whisper плохо транскрибирует RU тех-термины | Высокая | Передавать `--initial_prompt "Yandex Direct, MCP, API, Claude, Метрика"` |
| `video-edit` лагает на 60fps | Средняя | Снизить до 30fps |

**Главное правило MCP-рисков:** если шаг не получается с 3-й попытки за 1 час — переключаемся на ручную альтернативу для этого шага. Не доводим инструмент до идеала.

### Production

- Voice-tracks с разной громкостью → OBS audio-meter, цель −19 LUFS, разница >3 dB = перезаписать
- Face-cam дубли → минимум 3 дубля, лучший выбираем при монтаже
- Внешний шум → запись в нерабочие часы, новый дубль вместо чистки
- Не успеваешь за тайминг → режем фразу

### Контентные

- Шортс не заходит → пилот-запуск, ретеншн < 50% в первые 5 сек = переписать хуки оставшихся
- Требование удалить (клиент / Яндекс) → анонимизация: домен asiapk.ru размыт, ID аккаунтов скрыты, цифры округлены
- "AI-кринж" / "хвастливо" → тон сценария спокойно-аналитический, хук = факт без восклицания
- Обвинения в накрутке → готовы скрины Метрики до/после с датами, ссылка на public-репо

### Безопасность данных

- Yandex API token в кадре → переменные окружения скрыты, `.env` не открыт
- Имя клиента / контракты → blur-пятно через `video-edit` postprocessing, pre-record checklist
- Telegram-уведомления / личные письма → Focus-режим + закрыть мессенджеры + DND
- CRM Битрикс → не показывать в кадре

### Decision Tree

```
                          ┌─ ✓ Стабильно → продолжаем все 6 с MCP
                          │
Шорт #1 готов за 1 день ──┼─ ⚠ Местами лагает → 2-6 в гибриде MCP+CapCut
                          │
                          └─ ✗ Не работает → 2-6 в Подходе 2 (OBS+CapCut)


                          ┌─ Любая проблема → откат на Подход 2
Шорт #1 готов за 2-3 дня ─┤
                          └─ Если только screen-record фейлит → MCP только для монтажа

Шорт #1 не готов за 3 дня → STOP, ретроспектива, переподход
```

### Критерии успеха

| Уровень | Критерий |
|---|---|
| Минимум | 6 шортсов опубликованы и не удалены |
| Средний | Любой 1 ролик > 1000 просмотров на YouTube Shorts |
| Хорошо | Серия привлекла > 10 GitHub stars на репо |
| Отлично | Один ролик в рекомендациях, серия > 100 stars и DM от рекрутёров |

Цель серии — портфельная. Минимум-уровень = успех (серия существует, ссылается на GitHub, демонстрирует стиль работы автора).

## 9. Acceptance criteria

Дизайн считается реализованным успешно, если:

1. ✅ Все 6 шортсов экспортированы в `final/short-N.mp4` в формате 1080×1920 с длительностью ≤60 сек
2. ✅ Каждый ролик содержит face-cam intro (≤3 сек), screencast-середину, face-cam outro (≤6 сек)
3. ✅ Каждый ролик имеет word-level русские субтитры (Whisper-сгенерированные, ручная правка тех-терминов)
4. ✅ Каждый ролик содержит финальную on-screen графику с hook-цифрой и CTA-overlay
5. ✅ Звук всех 6 роликов имеет однородную громкость (целевая −19 LUFS, разница между роликами ≤2 dB)
6. ✅ В кадре нет токенов / приватных данных / имени клиента
7. ✅ Все 6 опубликованы на YouTube Shorts (минимум) согласно расписанию
8. ✅ В описании каждого ролика есть ссылка на GitHub-репо `SvechaPVL/yandex-mcp`

## 10. Что НЕ входит в этот дизайн

- Английская версия серии (можно сделать вторым сезоном, не сейчас)
- Длинное YouTube-видео по этой же теме (можно сделать после успеха шортсов)
- Habr-статья с embed (опционально как пост-публикационный контент)
- Реклама шортсов через бюджет (используем только organic reach)
- Создание Telegram-канала, если его нет (предполагается, что есть)
